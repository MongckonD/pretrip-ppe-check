# จับเวลาส่งสินค้าแต่ละร้าน (Time & Motion) — แบบร่าง

สถานะ: **ต้นแบบหน้าจอ** — ทดลองได้ในโหมดทดสอบ (`npm run dev` → แท็บ Time activities กล่อง "ร้านค้า")
ข้อมูลยังเก็บในเบราว์เซอร์เท่านั้น ยังไม่มีตารางในฐานข้อมูลจริง

แยกจากเวลาเริ่มงาน/จบงาน (กล่อง 1 และ 3) ทั้งหมด — ไม่แตะ `trip_activities`

## ขั้นตอนบนหน้าจอ

1. **เลือกร้าน** (ค้นหาชื่อ) หรือ **+ เพิ่มร้านใหม่** (ชื่อร้าน + ประเภท: ขายส่ง / เบ็ดเตล็ด / ร้านอาหาร / โรงแรม)
2. **▶ รถจอดหน้าร้าน — เริ่มจับเวลา** → เริ่มนับที่ A01
3. กด **ถัดไป ▶** ไล่ตามลำดับ A01 → … → D04 (กดครั้งเดียว = จบกิจกรรมเดิม + เริ่มกิจกรรมใหม่)
   - กดรหัสไหนก็ได้ในรายการเพื่อข้าม หรือย้อนไปทำซ้ำ (เช่น B02 เดินยกหลายรอบ — เวลารวมกัน)
4. **■ รถออกจากร้าน (D05)** → หยุดเวลา แล้วกรอก จำนวนลัง\*, SKU, ระยะทางรถ→จุดรับ (ม.), วิธีขนย้าย\* → **บันทึกร้านนี้**
   - กด D05 ผิด → "กลับไปจับเวลาต่อ"
5. **เวลาเดินทางระหว่างร้าน**: นับตั้งแต่กด D05 ของร้านก่อนหน้า (รถออก) จนกดเริ่มร้านถัดไป (รถจอด)
   - ระหว่างทางมีตัวนับ "🚚 กำลังเดินทางไปร้านที่ N" ให้เห็น
   - ร้านแรกของวันไม่มีเวลาเดินทาง
6. รายการ **ร้านที่ส่งแล้ววันนี้**: เวลาต่อร้าน, เวลาเดินทางมาจากร้านก่อนหน้า, แท่ง A/B/C/D, นาที/ลัง, สรุปรวมของวัน (รวมเวลาเดินทางรวม และเฉลี่ยต่อช่วง)

## รหัสกิจกรรม

| ช่วง | รหัส |
|---|---|
| A นอกร้าน | A01 จอดรถ/ดับเครื่อง · A02 วางกรวย · A03 เปิดรถ/เตรียมรถเข็น · A04 คัดแยกตามบิล · A05 ยกสินค้าลง · A06 จัดใส่รถเข็น |
| B เคลื่อนย้าย | B01 เดินตัวเปล่าไป · B02 เดินยกสินค้า · B03 เข็นรถเข็น · B04 เดินตัวเปล่ากลับ |
| C ในร้าน | C01 Check-in · C02 ตรวจนับส่งมอบ · C03 เข้าจุดเก็บ · C04 FIFO · C05 แช่ตู้เย็น · C06 จัดเรียง/โชว์ · C07 POSM · C08 รับคืนภาชนะ · C09 เอกสาร/ชำระเงิน · C10 ยืนยัน/กล่าวลา |
| D ปิดงาน | D01 เก็บภาชนะคืน · D02 เก็บรถเข็น · D03 ปิดประตูรถ · D04 เก็บกรวย · D05 รถออกจากร้าน |

> ในรูปต้นฉบับเขียน C19 — ใช้ C10 แทน (ลำดับต่อจาก C09) ถ้าตั้งใจเป็น C19 แก้ได้

## ตารางที่เสนอ (ยังไม่สร้าง)

```sql
-- ประเภทร้าน (ขายส่ง / เบ็ดเตล็ด / ร้านอาหาร / โรงแรม)
store_types (code PK, name, name_en, sort_order, active)

-- ร้านค้า: สร้างจากหน้างานได้ (ชื่อซ้ำในประเภทเดียวกันไม่ได้)
stores (id PK, name, store_type → store_types, active, created_by, created_at, updated_at)

-- รหัสกิจกรรม A01…D05 (ช่วง A/B/C/D, ลำดับมาตรฐาน)
visit_activities (code PK, phase CHECK IN ('A','B','C','D'), name, sort_order, active)

-- 1 แถว = ส่งของ 1 ร้าน 1 ครั้ง
store_visits (
  id PK, visit_date, vehicle_inspection_id → vehicle_inspections (รถ + ทีมของวันนั้น),
  store_id → stores,
  started_at, ended_at,          -- รถจอด / รถออก (เวลาจาก server)
  prev_visit_id → store_visits,  -- ร้านก่อนหน้าของวันเดียวกัน (ว่าง = ร้านแรก)
                                 -- เวลาเดินทาง = started_at − ended_at ของ prev_visit (คำนวณใน view ไม่ต้องเก็บซ้ำ)
  cases, sku_count, distance_m, move_method CHECK IN ('trolley','carry','both'),
  created_by, created_at, updated_at
)

-- ช่วงเวลาของแต่ละกิจกรรม (กิจกรรมเดียวกันมีได้หลายช่วง เช่น B02 หลายรอบ)
store_visit_segments (visit_id → store_visits ON DELETE CASCADE, seq, activity_code → visit_activities,
                      started_at, ended_at, PRIMARY KEY (visit_id, seq))

-- view สรุป: นาทีรวม, นาทีต่อช่วง A/B/C/D, นาที/ลัง ต่อร้าน — ใช้ทำ Pivot และค่าเฉลี่ยตามประเภทร้าน
v_store_visit_summary
```

## เรื่องที่ต้องตัดสินใจ

1. เวลาแต่ละกิจกรรม: **server ประทับเวลา** ตอนกดแต่ละครั้ง (กันแก้เวลา) แต่ถ้าสัญญาณหาย ต้องเก็บในเครื่องก่อนแล้วส่งทีหลัง?
2. จำนวนลังกรอก **ครั้งเดียวตอนจบร้าน** หรือแยกที่ A05 / B02 / B03 ด้วย?
3. ใครเพิ่ม/แก้ร้านได้ — พนักงานหน้างาน หรือ admin เท่านั้น?
4. หน้า admin: ตารางผลลัพธ์ตามประเภทร้าน (จำนวนตัวอย่าง, เวลาเฉลี่ย, เวลาคงที่, นาที/ลัง) + Pivot ต่อกิจกรรม + ดาวน์โหลด CSV สำหรับ Roadnet
